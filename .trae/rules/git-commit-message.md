# Git 提交信息生成规则

## 语言要求

- **使用中文（简体）**撰写提交信息

## 消息格式

### 单行提交（简短改动）

```
<类型>: <简洁描述>
```

### 多行提交（较复杂改动）

```
<类型>: <简洁描述>
```

## 类型（type）说明

**类型前缀使用英文小写**，后跟冒号 + 空格 + 中文描述。

| 类型       | 使用场景                      |
| ---------- | ----------------------------- |
| `feat`     | 新功能、新页面、新组件        |
| `fix`      | Bug 修复、问题修正            |
| `style`    | UI/样式调整（不影响功能逻辑） |
| `refactor` | 代码重构（无功能变更）        |
| `perf`     | 性能优化、体验改进            |
| `docs`     | 文档更新、注释补充            |
| `data`     | 站点数据、资源更新            |
| `chore`    | 脚本、构建配置、开发工具改动  |
| `test`     | 测试相关改动                  |

## 描述规范

- **必须使用中文（简体）**描述改动内容
- **简洁明了**：不超过 50 个字符
- **不使用句号结尾**
- **不使用大写英文缩写**（除非是项目内通用术语）

## 好的示例

```
feat: 顶部栏左侧公告按钮
fix: 移动端侧边栏展开时宽度不一致
perf: 站点卡片悬停动画更流畅
docs: 更新 CONTRIBUTING.md 贡献指南
feat: 新增 3 个 ACG 资源站点
refactor: 侧边栏逻辑抽离为独立模块
```

## 避免的写法

❌ 避免全英文描述

- `feat: add announcement button` → 应改为 `feat: 顶部栏公告按钮`

❌ 避免含糊不清

- `fix: 修复一些问题` → 应具体说明 `fix: 移动端侧边栏宽度异常`

❌ 避免冗长

- 超过 50 字的描述请放到正文部分详细说明

❌ 避免中文类型前缀

- `新增: 顶部栏公告按钮` → 应改为 `feat: 顶部栏公告按钮`
